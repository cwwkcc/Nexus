# Nexus — Content Approval Workflow

**How content is reviewed and published**

---

## Purpose

This document defines the workflow for creating, reviewing, and publishing content on the Nexus platform. All content must follow this workflow to ensure quality and accountability.

---

## Overview

### Content States

| State            | Description                                         |
| ---------------- | --------------------------------------------------- |
| **Draft**        | Content is being created, not visible to the public |
| **Under Review** | Content is waiting for approval                     |
| **Published**    | Content is visible to the public                    |
| **Archived**     | Content is no longer visible but retained           |

### Workflow Diagram

```
┌─────────┐    ┌──────────────┐    ┌───────────┐    ┌───────────┐
│  Draft  │───▶│ Under Review │───▶│ Published │───▶│ Archived  │
└─────────┘    └──────────────┘    └───────────┘    └───────────┘
     ▲                │                  │
     └────────────────┘                  │
     (Rejected)                          │
                                   (After expiry/
                                   after 1 year)
```

## Content Types and Approvals

### News Articles

| Step | Action            | Responsible   | Notes                         |
| ---- | ----------------- | ------------- | ----------------------------- |
| 1    | Create draft      | Editor        | Follow editorial guidelines   |
| 2    | Submit for review | Editor        | Notify Staff Advisor          |
| 3    | Review            | Staff Advisor | Check accuracy, tone, quality |
| 4    | Approve/Reject    | Staff Advisor | Provide feedback if rejected  |
| 5    | Publish           | Editor        | Set publication date          |
| 6    | Archive           | Editor        | After 1 year                  |

**Review Time:** Within 24 hours

**Escalation:**

- If Staff Advisor is unavailable, escalate to Principal
- Urgent announcements: Phone approval then publish

---

### Events

| Step | Action           | Responsible     | Notes                       |
| ---- | ---------------- | --------------- | --------------------------- |
| 1    | Create draft     | Event organiser | Include all details         |
| 2    | Self-review      | Event organiser | Verify dates and details    |
| 3    | Publish          | Event organiser | Immediate publication       |
| 4    | Update if needed | Event organiser | Update details before event |
| 5    | Archive          | Automatic       | After event date            |

**Review Time:** None (direct publishing)

**Note:** Events are published directly by the organiser. Accuracy is the organiser's responsibility.

## Approval Criteria

### General Criteria

All content must meet these criteria:

- [ ] **Accuracy** — Information is correct and up-to-date
- [ ] **Tone** — Formal but welcoming, reflects the school's voice
- [ ] **Quality** — Free of spelling and grammar errors
- [ ] **Accessibility** — Alt text for images, proper structure
- [ ] **Privacy** — No sensitive personal information
- [ ] **Appropriateness** — Suitable for all audiences

### News Articles

- [ ] Headline is clear and accurate
- [ ] Article is 300-500 words
- [ ] At least one image with alt text
- [ ] Correct category assigned
- [ ] Links are working and relevant
- [ ] SEO metadata is complete

### Events

- [ ] Date and time are correct
- [ ] Venue is specified
- [ ] Description is clear
- [ ] Registration link (if applicable) is working

### Gallery Photos

- [ ] All photos have alt text
- [ ] Photos are high-quality
- [ ] Album has a title and description
- [ ] Photos are appropriate for the school

## Content Review Checklist

### For Reviewers

Before approving content, confirm:

- [ ] Content is accurate and up-to-date
- [ ] Tone is appropriate for the school
- [ ] No spelling or grammar errors
- [ ] Images have alt text
- [ ] Links are working
- [ ] No sensitive personal information
- [ ] Content is suitable for all audiences

### For Editors

Before submitting content, confirm:

- [ ] I have reviewed my own work
- [ ] All information is accurate
- [ ] Images have alt text
- [ ] Spelling and grammar are correct
- [ ] I have followed the editorial guidelines
- [ ] I have added appropriate categories

## Content Removal

### When to Remove

| Reason                 | Action            | Responsible    |
| ---------------------- | ----------------- | -------------- |
| Inaccurate information | Immediate removal | Staff Advisor  |
| Inappropriate content  | Immediate removal | Principal      |
| Outdated content       | Archive           | Editor         |
| Staff changes          | Remove profile    | Administration |
| Privacy violation      | Immediate removal | Staff Advisor  |

### Removal Process

1. **Identify** the content that needs removal
2. **Verify** the reason for removal
3. **Archive** the content (soft-delete)
4. **Notify** the original content owner (if applicable)
5. **Document** the removal in the audit log
